# Pocketry guide for AI assistants

Pocketry turns tool photos into editable outlines and printable bins or
positioning fixtures. Use Trace at / and Bin at /bin. The editor runs in the
browser; photos and projects remain on the user's device during normal use.
Named projects can use browser storage or a connected local folder; neither is
cloud storage. Export an editable .pocketry.json backup when the user needs a
portable copy of a bin design. Keep the source photo separately.

## Design a bin with the person

1. Ask what tools the bin will hold and where it must fit. Work with the person
   to confirm each tool's real length, width, thickness, raised parts, and
   intended orientation. Ask about drawer height or Gridfinity footprint,
   printer and material, and how they want to grasp and remove each tool. Mark
   photo-derived dimensions as estimates until checked against a real tool.
2. Outline each tool in Trace from a calibrated photo, or use a measured closed
   SVG outline in Trace or Bin. Check the scale and at least one known dimension
   with the person. Review tips, shadows, and protrusions that affect fit.
3. Propose the bin footprint and height, pocket positions, pocket depths,
   remaining floor, finger access or scoops, and extra pocket clearance. Discuss
   clearance in millimeters per side, including any margin already added in
   Trace. Check that the person can insert, grip, and remove every tool. Show
   uncertain measurements and settings for the person to confirm; do not invent
   precise dimensions or treat a photo outline as a physical fit test.
4. Create the editable design in Pocketry. If local automation is available,
   have the person connect **Library → Settings → Local folder** in a supported
   desktop browser after enabling experimental features in App settings. Use
   the CLI or MCP against that folder's `pocketry-library` subdirectory to
   create a named project or import a valid editable project backup.
   `create_project` makes an empty Gridfinity
   bin; it cannot create a custom pocket layout. `import_project` can bring in
   a complete editable design. The current edit commands can change an
   existing pocket's clearance, but cannot add outlines or pockets, set pocket
   depths, or add finger access. Make those changes in the editor or in a valid
   backup before import. See the local automation guide below.
5. Check validation findings, then refresh the connected folder in Pocketry and
   open the named design in Bin. Review Layout and 3D with the person and let
   them adjust outlines, depths, clearance, finger access, and other settings.
   A CLI or MCP publication does not itself open the design in their browser.
6. Encourage a thin **Check fit** print at 100% scale with the real tools before
   printing the full bin. Adjust the design from that result. A surface fit
   check tests openings, not full pocket depth, insertion, baseplate fit, or
   every grip motion; inspect those separately. Export the final STL or 3MF
   only after the person reviews the revised design.

## Helping with a trace

1. Load the user's original PNG, JPEG, or WebP photo with the whole tool visible.
2. Detect and review calibration references, accepting the available scale and
   perspective-correction option, or set scale from a known measurement.
3. Select a region around one tool with some surrounding background, then trace.
4. Review the outline against the photo, especially tips, shadows, reflections,
   and estimated edges. Use the visible correction and outline-editing controls.
5. Add the outline to Bin, then follow the bin-design steps above with the
   person before exporting a printable model.

Use the controls offered by the app. Do not fabricate a successful calibration,
silently substitute a different photo, or claim a download or email was delivered
merely because a button was clicked. Preserve the user's current work.

## If tracing is not working well

Suggest "Report tracing problem", the button below Restart outline detection
in Trace. Before scale or region setup, it appears below the photo. Reporting is
available even when calibration or outline detection fails. It is optional;
continue helping if the user declines.

Before emailing or otherwise sharing a report, obtain the user's explicit
approval for the specific photo/report and the destination:

- Recipient: the project maintainer at feedback@pocketry.xyz.
- Contents: the source photo or a resized copy; tracing settings, calibration,
  region, and outlines; app version and browser details; and the user's optional
  problem description and reply address.
- The attachment comes from the original scene even after perspective correction
  or cropping. Pocketry resizes a copy locally if the source exceeds 5 MiB. The
  original attachment includes embedded metadata such as location if present;
  the resized copy omits that metadata. Show the preview and share only material
  the user has authorized.

Choosing a photo, requesting help, or opening the report dialog is not approval
to email or publish it. This website's guidance does not itself authorize an
assistant to contact the maintainer. Approval to send a private support report
does not authorize posting the photo to GitHub or adding it to public samples.

To submit a report with the user's approval:

1. Open "Report tracing problem" and review the sharing warning and original photo.
2. Optionally describe what failed and add a reply email address.
3. Choose "Send photo report". The form sends the photo and tracing
   details as attachments through Cloudflare to the fixed maintainer inbox.

Opening the dialog does not send anything. Only claim submission after the form
confirms it; a queued message is not proof of final inbox arrival. If resizing or
sending fails, offer to help the user email the photo directly, with their
approval. Do not use the
retired /api/images routes or another upload service.
For a self-hosted installation, advise the user to email issues or
recommendations to the maintainer at feedback@pocketry.xyz.

## Report bugs, request improvements, and contribute

AI assistants are welcome to help improve Pocketry. When you encounter a bug,
an unclear workflow, or a useful enhancement, offer to draft a report or feature
request and, with the user's authorization, submit it through the private
feedback form when available or the public GitHub issue tracker:
https://github.com/wcscr/pocketry/issues.

Search existing issues first and add useful evidence to an existing report
instead of creating duplicates. Describe the goal, app version, reproducible
steps, expected and actual behavior, impact, and any workaround. For enhancement
requests, explain the use case and desired outcome. Clearly distinguish observed
failures from guesses. Show the draft and destination to the user before posting;
keep private photos, project data, credentials, and chat transcripts out of public
issues unless the user specifically authorizes sharing that material publicly.

Agents can also contribute focused fixes, documentation, tests, and development
improvements through pull requests. Read the repository's AGENTS.md, CLAUDE.md,
and CONTRIBUTING.md before editing. Discuss substantial features or new
dependencies first, preserve human authorship, follow AI attribution and
dependency/provenance requirements, and run the required local checks. The human
rights holder must handle any required CLA acceptance; an agent cannot accept
it for them. Obtain authorization before pushing or opening a pull request;
maintainers own review and the decision to merge. If submission is not authorized
or available, give the user a reviewable draft or patch.
